kintone GPT Plugin（OpenAI Responses API 対応）
kintone のレコード画面に 「AIに問い合わせ」ボタン を追加し、フィールドに入力した内容を OpenAI の AI に送信、その返答を別のフィールドへ自動で書き込むプラグインです。PC・モバイルの両方に対応しています。

できること

フィールドに入力した文章をワンクリックで AI に送信し、返答を自動で受け取れます
AI の役割や口調、出力ルールをあらかじめ固定できるため、毎回同じ指示を書く必要がありません
思考の深さ（Reasoning）を調整でき、用途に応じて回答の精度とスピードのバランスを変えられます


事前準備（kintone アプリ側）
プラグインを使う前に、kintone アプリのフォームで以下の 3 つを用意してください。

入力用フィールド — AI に送りたい文章を入力するフィールド（例：複数行テキスト、フィールドコード CONTENT）
返信用フィールド — AI の返答が書き込まれるフィールド（例：複数行テキスト、フィールドコード REPLY）
スペース（要素ID付き） — 「AIに問い合わせ」ボタンを表示する場所です。フォームに「スペース」部品を配置し、要素ID を設定してください（例：gpt_space）


補足： ここでいう「スペース」は、フォーム上に配置するスペース部品のことです。kintone の「スペース」機能（コミュニケーション用）とは別物ですのでご注意ください。

API Key の安全性について： バージョン3以降では、API Key は kintone のプラグイン専用の仕組み（Proxy）にのみ保存します。通常のプラグイン設定にはキーを含めません。既存キーは管理者のプラグイン設定画面でのみ読み込み、入力欄では伏せ字で表示します。一般利用者のレコード画面にはキーを渡しません。

旧版からの移行（各アプリで一度実施）

1. 修正版のプラグイン（バージョン6）をkintoneにインストールします。
2. 利用している各アプリのプラグイン設定画面を開きます。既存のProxy設定のキーを自動で引き継ぎます。Proxy設定がない旧環境では通常設定のキーを引き継ぎます。
3. 設定を保存します。Proxy設定の保存成功後に通常設定から旧APIキーを取り除きます。キーの再入力は不要です。
4. 「アプリを更新」を実行します。PC・モバイルの「AIに問い合わせ」操作は従来どおりです。

プラグインのインストールだけでは旧設定のキーは消えません。各アプリで設定保存とアプリ更新が必要です。移行後は通常設定にキーの実値が残っていないこと、設定画面を開き直しても再入力なしで保存できることを確認してください。保存完了の案内が出ない場合はアプリを更新せず、設定画面を再読み込みして保存し直してください。


使い方

レコードの 新規作成 または 編集 画面を開く（PC / モバイル）
フォーム上に表示される 「AIに問い合わせ」 ボタンを押す
入力フィールドの内容が AI に送信され、返答が返信フィールドに自動入力されます


ご注意ください

情報の取り扱い： 入力した内容は OpenAI のサーバーに送信されます。機密情報や個人情報を送信してよいか、社内のルール・規定を必ず確認してください。
利用料金： OpenAI API は従量課金制です。利用量に応じて費用が発生します。
設定ミスにご注意： スペースの要素ID やフィールドコードが間違っていると、ボタンが表示されない・書き込みエラーになるなどの不具合が起きます。
対応画面： レコードの新規作成・編集画面のみ対応です。レコード詳細（閲覧）画面では動作しません。

バージョン4の動作

- 問い合わせは画面ごとに1件ずつ実行します。処理中はボタンが「問い合わせ中…」になり、再クリックを受け付けません。
- 回答反映時に、他のフィールドの編集内容を保持します。待機中に入力または返信を変更した場合は、自動反映を止めて通知します。
- レコード保存を試みたときや画面を移動したときは、待機中の回答を反映しません。再表示時にボタンが重複しないようにします。
- 設定保存時は、変更中のフォームのフィールドとスペースを検証します。検証に失敗した場合は、APIキーを含めて設定を保存しません。
- 入力・出力はテーブル外の文字列（1行・複数行）に対応します。リッチエディター、複数選択などは対象外です。出力先は自動計算・ルックアップ・ルックアップのコピー先を指定できません。
- 出力先は文字列（複数行）を推奨します。1行フィールドに改行を含む回答や、文字数制限に合わない回答は反映しません。回答の自動切り詰めはしません。
- 問い合わせ前にも運用中のフォーム情報とレコードを検証します。フィールドの削除、型の変更、取得できないフィールド、編集不可の出力先があれば送信を止めます。
- 正常完了した回答だけを反映します。未完了、回答拒否、空の回答、不正なJSON、通信エラーでは既存の返信を保持し、エラーを8秒間表示します。
- フォーム情報取得は15秒、問い合わせ全体は180秒でタイムアウトします。ボタンは再度操作できますが、遅れて届いた結果は反映しません。画面側のタイムアウトや画面移動は、OpenAI側の処理や課金を停止するものではありません。自動再送は行いません。
- 回答が入力された後は、レコードの保存が必要です。

開発時の検証

ローカルに `tests/` がある環境では、`npm test` で設定保存とPC・モバイルの模擬テストを実行できます。外部APIへの送信は行いません。`tests/` はGit管理対象外のため、新規cloneには含まれません。
実際のkintoneでは、テスト用アプリで設定保存・アプリ更新・各画面の問い合わせ・アクセス権による動作を確認してください。
`src/js/common.js` が共通処理で、`desktop.js` と `mobile.js` は画面APIとUI部品を渡します。

バージョン5のモデル設定

- GPT-6 Astra（`gpt-6-astra`）を追加し、推奨モデルと新規設定時の初期値にしました。
- 保存済みのGPT-5.6 Sol／Terra／Luna、GPT-5.5は引き継ぎます。既存アプリでAstraを使う場合は、設定画面で選択して保存し、アプリを更新してください。
- Astraの思考設定は `low / medium / high / xhigh / max` です。本プラグインの初期値は `medium`。Astraで使用できない `none / minimal` は `low` に変換します。設定画面・PC・モバイルに同じ制限を適用します。
- [OpenAI公式モデル仕様](https://developers.openai.com/api/docs/models/gpt-6-astra)と[移行ガイド](https://developers.openai.com/api/docs/guides/latest-model)に基づきます。

バージョン6の修正

- 追加・編集画面で空の文字列フィールドが `undefined` として返る場合に、出力フィールドを型エラーにしていた不具合を修正しました。`undefined`・`null`は空文字列として検証・比較します。
- 空の返信欄へ回答を反映でき、空の入力欄には入力を促す通知を表示します。配列などの不正な値は従来どおり拒否します。

フォルダ構成

プロジェクトのルート直下に `src/`、`scripts/`、`package.json` を配置しています。配布ZIPは最新版の `dist/plugin.zip` のみです。

- `src/`：プラグインのコード・設定画面・画像・manifest
- `scripts/`：開発用の起動スクリプト
- `dist/plugin.zip`：最新版（バージョン6）の署名済みプラグイン
- `node_modules/`、`test/`、`tests/`、`Microsoft/`、`Windows/`：Git管理対象外
- `private.ppk`：ローカルで保持する署名鍵。Git管理対象外

ルートディレクトリで `npm ci` を実行して依存ライブラリを準備し、既存プラグインの署名鍵を `private.ppk` として配置すると、`npm run build` で `dist/plugin.zip` を生成できます。同じプラグインとして更新する場合は、同じ署名鍵を使用してください。
