# バージョン7 レコード画面の実装メモ

## 変更内容

- GPT-6.2 Astra と GPT-6.2 Sol を追加し、未保存・未対応のモデルは GPT-6.2 Astra に解決する。保存済みの対応モデルは引き継ぎ、モデルごとの許可値に合わせて思考の深さを正規化する。
- 6.2 系のシステムプロンプトは先頭の developer メッセージとして送信し、入力本文を user メッセージにする。従来モデルはトップレベルの `instructions` と文字列の `input` を使う。
- PC・モバイルのレコード画面を KUC に依存しない DOM パネルに変更した。状態メッセージは次の操作や画面遷移まで表示し、回答の反映成功時に Proxy の応答時間を小数1桁で表示する。設定未完了の場合はパネルでボタンを無効にし、フォームのスペースがない場合はヘッダーにエラーを表示する。仕様書のスタイルを `panel.css` に追加し、旧 CSS 3 ファイルを削除した。
- PC・モバイルのランタイムテストを DOM モックに差し替えた。リクエスト形式、思考の深さ、パネルの状態・再表示・ヘッダー表示に加え、遅延応答の破棄、15秒・180秒のタイムアウト、再送なし、空値の扱い、書き戻し確認を検証した。

## 検証結果

- `npm.cmd test` は64件すべて成功。ランタイムは PC・モバイル各19件。並行作業中の設定画面テストも実行時点では全件成功した。
- `node node_modules/eslint/bin/eslint.js src/js/common.js src/js/desktop.js src/js/mobile.js` は、標準のローカル環境では Prettier が見つからず起動できなかった。既存の npm キャッシュにある Prettier 3.9.10 を一時ディレクトリに展開し、`NODE_OPTIONS` で読み込み先を指定して同じコマンドを実行した結果、エラー0件、既存の警告2件（`loadForm` の `consistent-return`、`readResponse` の `no-nested-ternary`）。
- `panel.css` が仕様書4章の CSS と一致することを確認した。

## 未確認

- 実際の kintone 上での PC・モバイルの表示、ヘッダースペースの取得、OpenAI Proxy 経由の通信、配布 ZIP は未検証。
